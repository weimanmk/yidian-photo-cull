# 筛图可靠性改进记录

基线：`46428f9`（v0.2.1）。本记录描述尚未发布的源码改动，不替代真实数据集验收。

## 四项目标核对

| 目标 | 基线已有能力与缺口 | 本次落实 | 仍需验证 |
|---|---|---|---|
| 废片筛查 | 多阶段人脸、主体、曝光和画质证据已存在；评星层仅检查可解码，组内起始候选和预算可能把低质量片升为 3 星 | 自动 3 星、普通 2 星储备及 1 星统一质量准入；允许整组无精选；0 星文案为未入选并展示具体原因 | 55 分及硬问题阈值在不同活动上的误杀率；质量警告不是人工真值 |
| 相似图识别 | 场景归组和相邻组二次合并已存在；严格重复簇仍按组构建，生产簇自身的零泄漏不能排除漏检 | 全局候选与簇内全成员兼容检查；保留动作/人脸变化；最终星级独立人工照片对审计 | 跨远距离裁切、重编码副本可能漏检；完全兼容检查在大簇中可能增加开销 |

## 三项优先改进及取舍

1. **质量准入与可解释评级**。基线用低分单图即可复现自动 3 星，属于直接影响交付的错误，不必等待新模型。涉及 `rating_policy.py`、`coverage.py`、结果检查器及策略测试。收益是阻止起始选片、预算补齐和模型回退绕过质量要求；主要风险是阈值误杀，所以可保留明确标记待复核的唯一覆盖片，并优先尊重人工锁定。这比先训练个性化权重更值得做，因为软排序无法修复不合格候选进入精选的问题。

2. **全局严格去重与独立评估**。基线按组建立严格簇，跨组副本可同时精选；历史报告的生产簇零泄漏属于自洽性指标。涉及 `near_duplicates.py`、`audit.py`、两份评估脚本及独立标签测试。收益是消除组边界造成的重复，并让漏合并/误合并可以被外部标签发现。风险是更保守的全成员兼容检查会降低召回并增加大簇成本。因此不把远距离同背景图直接合并，也不宣称新真实集指标。这比继续堆场景模型更优先，因为原有信号已能识别的副本会在决策层丢失约束。

3. **人物证据稳定性与人工纠错闭环**。静默人数截断、低质量身份传播与不可修正的聚类会同时损害分组、排序和覆盖。涉及 `face_engine.py`、`face_quality.py`、`identity.py`、`identity_corrections.py`、扫描/API/schema、结果页对话框及回放测试。收益是合影证据更完整、输入顺序更稳定，用户能修复错误身份且后续重扫保留决定。风险是计算量上升、未知身份增加和几何回放失配，因此提供重试诊断、冲突拒绝、复核提示及重扫提示。这比先做参与者名单库更值得做：名单不能补救不稳定的基础身份链，且引入新的录入与隐私管理成本。

依赖瘦身、模型替换、GPU 性能优化和偏好重训仍有价值，但本次三项直接约束交付正确性，不增加生产依赖、不下载新模型、不改原片，也不改评分权重。完成独立真值回归后再据耗时与误差分布决定这些后续工作。

## 纠错与评估契约

- 人物修正使用项目 ID、身份修订号及人脸引用，拒绝过期项目、过期修订和同图人物合并。项目原子保存后才更新内存结果。
- 来源目录内回放人工身份及锁定星级。旧项目仅在保存的绝对路径与相对路径一致时恢复来源；文件移动/变化导致 ID 改变时不猜测。检测框轻微变化后再次纠错会替换可唯一匹配的旧锚点。
- 身份修正后原星级保留，排名和覆盖需重扫；评估脚本拒绝尚未重扫的项目。扫描期间拒绝切换项目、修改身份和语义星级，避免人工决定与扫描快照竞争。
- 全部照片保存可靠人物×环节观测键，评估按最终 3 星或 2+3 星重新计算覆盖。覆盖仅针对模型观测到的可靠人物。
- 人工成对标注必须显式声明来源，拒绝未知 ID、自配对、重复/矛盾配对和非布尔标签。precision/recall 仅描述已标注对，不外推全库。
- 新扫描保存流水线版本、设置、模型哈希和可获得的代码哈希；评估另外保存项目/标签文件哈希及自身版本。旧项目或打包环境缺少来源证据时标记未知，不拿当前评估器冒充历史扫描版本。

## 验证记录

- Python 3.12 环境完整后端测试：276 通过、3 跳过、11 失败。新增算法、API、身份回放和评估回归均通过。
- 9 项失败要求本地真实模型文件（YOLO、OSNet、Depth、场景、人脸、眼睛、表情、关键点/FIQA、姿态），本环境缺少这些文件。
- 另 2 项 Lightroom 样例计划哈希失败已在原始 `46428f9` 独立工作树复现；本分支未修改 Lightroom 协议或样例，未掩盖失败。
- 前端 3 项交互测试通过；TypeScript 检查、生产构建与 `verify:ui` 通过。
- 独立代码审查发现并修复了旧项目来源恢复、修正后评估报错、重扫人物汇总及移动人脸框后再次纠错的回放问题。
- 未运行 5,379 张真实原图回归、Windows CUDA/DirectML 或真实 Lightroom 写入验收；历史数字与当前模型文件哈希不一致的事实已在 `REAL_SET_REPORT.md` 顶部注明。不能据单元测试声称准确率、召回或性能提升。
