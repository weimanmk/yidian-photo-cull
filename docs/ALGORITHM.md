# 一点筛图 v0.2.1 算法说明

本文对应发行版 `v0.2.1`。算法全程在本机运行；发行包不含 Qwen、GGUF、mmproj 或 llama.cpp。

## 目标

算法将两个问题分开处理：

1. 哪些照片属于同一个可比较画面组；
2. 同组照片中哪一张最值得保留。

这样可以避免用单一“综合分”直接筛全目录，也避免高分重复照被全部选中。

## 处理链路

```text
目录发现与 RAW 解码
        ↓
DINOv2 图像向量 + 感知特征 + 人脸/眼睛/表情/FIQA + 人体 ReID/3D 骨架 + 相对景深 + 画质特征
        ↓
ArcFace 跨照片人物聚类
        ↓
第一阶段：时间候选窗内联合场景分组
        ↓
第二阶段：跨组重复泄漏校验
        ↓
原图人脸清晰度复核 + 组内排序与保留 N 张
        ↓
技术分接近候选组的可选本地 VLM 复核（仅源码运行）
        ↓
严格近重复聚类 + 冻结语义评星模型
        ↓
3 星精选 → 2 星人物×环节补位 → 1 星其他价值 → 0 星废片
        ↓
人工复核 → Lightroom 原位写星 / 分级文件夹导出
```

相机同时拍摄 RAW+JPEG 时，同目录、同文件名的全尺寸 JPEG 被视为 RAW 的分析预览：项目、缓存键和导出仍绑定 RAW，但场景、人脸和画质直接读取同一拍摄的 JPEG，避免重复计数和昂贵的 RAW 全图显影。没有伴随 JPEG 时自动回到 rawpy；只有 JPEG 或位于不同目录的同名成片仍会独立分析。

## 场景相似度

每张照片提取多类互补视觉信号：

| 信号 | 作用 | 抗变化能力 |
|---|---|---|
| DINOv2-Small 384 维向量 | 判断画面内容与场景 | 裁切、姿态、变焦、局部动作 |
| YOLOv8n + OSNet 512 维向量 | 无正脸时补充人体外观一致性 | 远景、背脸、侧脸 |
| InsightFace 1k3d68 | 68 点三维人脸与精细 yaw/pitch/roll | 侧脸、低头、姿态异常 |
| BlazePose GHUM Heavy | 33 点二维骨架与人体世界坐标 | 人体平移、尺度、机位变化下的动作阶段 |
| Depth Anything V2 Large | 相对前后景与主体深度掩膜 | 舞台海报假人体、前景遮挡、背景层次 |
| eDifFIQA(T) | 对齐人脸感知质量分 | 模糊、低清、遮挡、光照不佳 |
| 灰度布局向量 | 比较主体和背景结构 | 亮度整体变化 |
| pHash | 识别近像素重复 | 轻微压缩、缩放 |
| dHash | 补充局部梯度重复 | 轻微曝光、压缩变化 |
| HSV 色彩直方图 | 比较色彩分布 | 局部位移 |
| 边缘布局 | 比较结构细节 | 色彩变化 |

联合分组先按 DINO 图像向量 `40%`、真实拍摄时间 `20%`、人物证据 `15%`、pHash/dHash `15%`、构图 `10%` 形成基础分；景深布局可用时再以 `5%` 软融合并重新归一。人物证据优先使用 ArcFace 身份集合；任一侧缺少可靠人脸时，才用 OSNet 一对一人体外观匹配校正该项。OSNet 受服装和队服影响，只能软加减分，不能形成身份硬约束。没有 AI embedding 时，其余信号会重新归一，不使用一个孤立余弦阈值直接下结论。

默认均衡阈值为 `0.73`；谨慎和激进分别为 `0.81`、`0.66`。阈值基于真实活动照片的 DINO 余弦分布初始化，并继续通过人工选片集校准。

## 人物身份的双门槛

活动全身照中的主角人脸通常很小。把所有小脸都当硬约束会因侧脸和运动模糊造成错误拆组；完全忽略又会把固定背景下的不同人物合在一起。因此使用两层证据：

- 支持证据：面积和置信度达到较低组合门槛后，可证明两张照片可能是同一人物。
- 冲突证据：只有更大、更高置信度的人脸才可触发“不同人物不得合组”的硬约束。
- 活动全景的超小脸使用单独通道：面积可低至约 `0.06%`，但必须达到更高检测置信度；避免把背景插画误当人物。

ArcFace 聚类还禁止同一张照片里的两张脸落入同一身份，避免多人合影发生身份坍缩。睁闭眼判断融合 106 点眼部几何与独立 CNN，优先使用随发行版打包、输入定义明确的 OpenVINO `open-closed-eye-0001`，旧版 MobileNet 仅作回退。106 点与 3D68 坐标回归严格按 InsightFace 官方实现输入 RGB `0..255`，避免重复归一化导致五官关键点坍缩；3D68 输出用于精细头部姿态。七类表情由 OpenCV Zoo MobileFaceNet FER 推理，并与嘴部关键点信号融合；它只参与同组优选，不参与人物身份判定。

## 3D 动作与景深联合证据

BlazePose GHUM Heavy 输出 33 个图像关键点和以髋部为原点的世界坐标。世界坐标先转换到人体自身的左右、上下、前后坐标轴，再按肩宽、髋宽和躯干长度归一，因此动作描述子弱化了人物在画面中的平移、缩放和相机旋转。它只判断“动作是否相近”，不会替代 ArcFace 身份。

固定舞台常含人物海报、卡通画或屏幕内容，单独的姿态检测器可能把它们当真人。Depth Anything V2 Large 先估计相对深度，再比较骨架附近深度与局部背景：真实前景人物获得较高前景分，贴在墙面上的图案被降权。多人合影会保留处在同一前景层的多个主角，不按单一最大人体粗暴裁掉。

景深模型输出的是场景几何，不等于摄影意义上的“是否合焦”。系统将主角深度带生成的掩膜与 Sobel/Laplacian 局部高频能量结合，得到主体合焦分和背景虚化分；主体合焦只以最高 `20% × 深度置信度` 的权重修正原运动模糊分。景深布局只作场景软证据，绝不进入人物身份硬约束。

## 二次去重

第一阶段分组刻意保守。第二阶段只检查时序邻近组，并再次比较组内照片对：

- 明确的人物身份冲突：拒绝合并；
- 同一稳定人物、场景接近且时间连续：允许更低的场景阈值；
- 无可靠正脸时：必须同时满足更高的时序、语义和结构门槛；
- 曝光变化时：亮度归一布局和语义特征可弥补色彩/pHash 下降。
- 每个预设限制成组的真实 EXIF 总时间跨度；缺少 EXIF 时回退到文件序号跨度。这样可避免 A≈B、B≈C 的传递链把多个动作时刻串成一个超大组；只有首尾也属于强重复时才允许有限放宽。

候选照片对会先通过全部安全门槛，再在有效候选中择优，防止“总分最高但时间较远”的照片对遮蔽真实边界。

二次合并按 EXIF 时间排序；当右侧组已经超过当前预设的候选时间窗时，后续组必然更远，立即停止该方向比较。该剪枝不修改相似度或合并门槛，可避免数千张固定机位照片反复扫描不可能命中的组对。

## 组内优选

组内排序先执行硬约束，再计算组内相对分：

1. 闭眼数量更少；
2. 不缺失本组主要人物；
3. 半闭眼更少；
4. 严重问题更少；
5. 主要人物覆盖更完整；
6. 多人照最差人脸质量更高；
7. 原图人脸、眼区清晰度与景深辅助主体合焦更好；
8. 综合曝光、技术质量、构图和表情更好。

人像组内分使用：人脸质量 `25%`、睁眼 `15%`、主体清晰度 `15%`、曝光 `10%`、表情 `10%`、审美代理 `10%`、技术质量 `10%`、构图 `5%`。主体清晰度以原运动模糊分为主，景深主角合焦分按置信度最多修正 `20%`。单脸质量在 eDifFIQA 可用时由清晰度 `24%`、眼区清晰度 `13%`、睁眼 `22%`、3D 头部姿态 `8%`、可见性 `11%`、eDifFIQA `22%` 构成；模型缺失时自动恢复原有确定性规则。多人照的人脸质量按平均脸 `35%`、最差脸 `40%`、主角脸 `25%` 计算。没有可靠人脸时改用技术质量、主体清晰度、曝光、构图和对比度。

## v0.2.1 语义评星

评星层不重新训练或修改上游视觉模型。它使用版本化的冻结轻量排序模型 `backend/photocull/assets/rating_model_v1.json`，在已完成的分组、人物识别和画质分析上分配 0–3 星。每次运行只做推理，不用当前活动数据拟合，也不允许按活动注入特例参数。

| 星级 | 语义 | 选片约束 |
|---|---|---|
| 3 星 | 精选 | 主交付集；每个可用分组至少有一个起始候选，但同一严格近重复簇最多只留一张 |
| 2 星 | 人物×环节补位 | 先补人物和环节硬缺口，必要时允许引入近重复；普通交付储备不再重复已覆盖的严格簇 |
| 1 星 | 其他有价值 | 每组最多补一张独立备选；必须可解码、质量分不低于 55，且无决定性问题 |
| 0 星 | 废片 | 无法解码、技术质量明显不合格、严格重复或其他未入选照片 |

严格近重复簇要求照片对同时满足强重复和人物兼容性；动作时刻 `beat` 还要求场景相似度不低于 `0.90`、可用时姿态相似度不低于 `0.90`、文件序号跨度不超过 `3`、时间跨度不超过 `4` 秒。

3 星层将冻结模型分与稳定通用分按 `75% / 25%` 融合；通用分由通用组内分 `58%` 和组内排名百分位 `42%` 构成。已被选中的动作时刻和分组会分别产生 `0.10` 与 `0.55` 的降权，以抑制多张高分重复照同时进入精选。系统以约 `35%` 精选缩减率和约 `25%` 交付集缩减率作为软目标，实际数量受分组数、严格去重、可靠人物覆盖和可用候选限制，不会为追求固定比例强行选入差片。

人工设置的星级会标记为 `manual` 并锁定，后续重跑不会被自动评星覆盖。`is_best_pick` 对应 2 星及以上的交付集，3 星仍是严格精选集。

## 人物 × 环节覆盖保底

质量分只能回答“哪张更好”，不能单独满足“每个环节每个人都必须有照片”的活动交付约束。开启覆盖模式后，系统在所有分组、排序和可选 VLM 复核结束后再执行一次全局校验：

1. 若素材使用多个一级子目录，直接把目录当作显式环节；否则按真实 EXIF 时间与用户设定的 `5–60` 分钟窗口分段，同一连拍组不在边界被拆开。
2. 只纳入在至少两张照片中稳定出现的身份；单次出现必须同时满足高可信和较大人脸占比，防止背景路人、海报和屏幕人脸扩选。
3. 建立“环节 ID × 人物 ID”覆盖矩阵，已有精选照片覆盖的单元不再增选。
4. 对缺口单元优先处理候选最少的人物，在其候选中按闭眼、严重质量问题、半闭眼、人脸质量、主体合焦和曝光顺序选取“风险最低”的一张。一张多人照可一次补齐多个缺口，避免不必要的数量膨胀。
5. 保底片进入 2 星交付集，但保留原始闭眼、模糊、曝光等警告，并单独标记为“覆盖保底”。这是交付保险，不是将差片伪装成 3 星精选。

自动模式只能保证“模型确实观测到的可靠人物”的覆盖。如果要对一份确定参与者名单做严格验收，还需要名单/参考人脸库；当前不会凭空声称已覆盖从未被拍到或始终无可识别人脸的人。

## 摄影师偏好 Ranking

偏好层比较逐张 Logistic Regression 与成对 Learning-to-Rank 两个轻量目标，不重新训练 DINO 或人脸大模型，并按整组验证自动采用较优者。输入除绝对画质外，还包含同组相对综合分、相对人脸/睁眼/运动模糊/曝光/构图、组内百分位和组大小。执行顺序固定为：

1. 先完成人物聚类和同场景分组；
2. 计算不含人工偏好的通用组内分与相对特征；
3. 应用本机摄影师偏好概率；
4. 闭眼、缺少主要人物等硬约束仍优先；
5. 偏好分只修正合格候选之间的软排序。

训练验证按完整照片组分块，禁止同一连拍同时进入训练集和验证集。逐张与成对目标、以及通用分与偏好分的混合权重，都由组隔离交叉验证选择。只有人工组选中 Top-1 或成对排序显著优于通用规则时才启用个性化权重；全局保留过滤使用更严格的 AUC 和 F1 提升门槛。模型不足时自动把权重降为零，避免为了“个性化”而降低可靠性。

默认偏好模型只作用于其训练素材目录；换到另一场赛事时自动回到通用排序，避免把某一批次的构图和人物分布误当成普遍摄影偏好。只有经过多数据集验证并显式标记为 `global` 的模型才允许跨目录使用。新训练若未通过启用门槛，也不会覆盖已有已验证模型，除非显式要求替换。

## 视觉大模型疑难组复核

视觉大模型是可选的组内软排序层，不参与全库分组，也不替代专业检测器。执行顺序为：

1. 完成场景分组、人物一致性与技术排序；
2. 排除闭眼、主体失焦、遮挡、缺少主要人物和明显曝光问题；
3. 只选择前两名技术分差小于配置门槛的疑难组，并限制总组数；
4. 每组默认取 2-4 张候选图合成一张带照片 ID 和主人脸裁剪的联系表（高级设置可调大）；
5. 本地 VLM 仅比较表情、神态、动作、互动、构图、氛围和瞬间价值；
6. 返回值必须通过严格 JSON schema、照片 ID 白名单、排名唯一性和置信度校验后才能应用。

把多张照片先合成单张联系表，可避免多图接口中的临近图片丢失/合并问题，也可显著降低视觉 token 和重复编码成本。模型服务只允许 `127.0.0.1`/`localhost`；启动失败、超时、无效 JSON、未知照片 ID 或低置信度都会保留原技术排序。

`v0.2.1` 标准安装包强制关闭这一可选接口，也不分发任何 Qwen 权重或推理程序。它只供源码运行时连接用户自行部署的本地兼容服务，不影响默认筛图链路。

## RAW 时间与两阶段细节复核

RAW 的拍摄时间直接从 `DateTimeOriginal + SubSecTimeOriginal` 读取，不再用文件复制后的修改时间代替。EXIF 完整时以真实时间控制分组跨度，文件序号只作缺失时间时的回退；Panasonic `P1132697 → P1142698` 这类目录前缀变化会归一为连续计数。第一阶段在 1600px 预览上完成 DINO、人脸检测和聚类；第二阶段按归一化人脸框回到原分辨率照片裁切，计算人脸与眼区清晰度。超小脸的闭眼分类只作软证据，避免把上采样噪声当成硬淘汰理由。

## Lightroom 与文件夹交付

Lightroom Classic 路径采用“原位加入 + 直接写星”，不复制、不移动、不改名原片，也不创建收藏集。操作前插件只读预检“新增 / 更新 / 不变 / 保护 / 无效”；已有 4 星和 5 星被视为人工高星并保护，不会降级。执行后使用目录和文件指纹回读核对，生成机器可读回执，再切换到图库网格、激活来源文件夹并选中本次照片。

文件夹交付会按用户选择的最低星级复制原片到 `3星精选`、`2星补位`、`1星有价值`。导出前检查同名冲突，不覆盖内容不同的文件；复制后比较源文件与输出文件的 SHA-256。该路径不写 XMP，因此不会在原片旁创建或修改 sidecar。

## SQLite 特征缓存

`cache.db` 分开保存照片特征、人脸特征、人体外观、3D 姿态、景深布局、模型签名、人工操作和 VLM 组内决策。图像、人脸、人体、姿态和景深描述子以 float16 BLOB 保存；人物 ID 和分组每次重算。VLM 缓存键包含候选成员、文件签名、技术事实、模型 ID、量化和 Prompt 版本；同组重跑时不会重复消耗大模型推理。

## 预设边界

- 谨慎：宁可多留，不轻易跨构图合组。
- 均衡：活动连拍默认，重点消除变焦、连续动作和曝光变化造成的拆组。
- 激进：优先减少重复，适合高帧率连拍；建议把每组保留数设为 2，兼顾全景和特写。

所有自动决策均可在结果页人工改为 0–3 星；人工星级会被锁定，并作为后续 Lightroom 或文件夹交付的权威值。
